[PRIORITÉ HAUTE] Détection de conflits d'horaires trop stricte
================================================================================

DESCRIPTION:
La fonction verifierDisponibiliteInscription() dans 
api/src/services/inscriptions/core/validation/queries.ts détecte des conflits 
d'horaires même lorsque les cours ne se chevauchent pas réellement.

SYMPTÔMES:
- Utilisateur 1 inscrit aux cours 1 (18:00-19:30) et 2 (19:00-20:30)
- Tentative d'inscription au cours 3 (14:00-15:00)
- Résultat: 2 conflits détectés (alors qu'aucun chevauchement d'horaire réel)

LOCALISATION DU CODE:
Fichier: api/src/services/inscriptions/core/validation/queries.ts
Fonction: verifierDisponibiliteInscription()
Lignes: ~35-95

LOGIQUE ACTUELLE:
La fonction vérifie les conflits en comparant:
1. Si l'utilisateur est déjà inscrit (OK ✓)
2. Si date_cours est identique (problème potentiel)
3. Si les horaires se chevauchent via heure_debut/heure_fin

PROBLÈME IDENTIFIÉ:
La condition de chevauchement semble comparer les horaires même sur des dates 
différentes, ou la logique de comparaison des heures ne fonctionne pas 
correctement.

Code actuel (approximatif):
```typescript
const conflits = await prisma.inscriptions.findMany({
  where: {
    utilisateur_id: utilisateurId,
    status_id: true,
    cours: {
      date_cours: cours.date_cours, // Même date
      OR: [
        // Logique de chevauchement d'horaires
      ]
    }
  }
});
```

CONTOURNEMENT TEMPORAIRE:
Dans le test d'intégration (inscriptions.service.integration.test.ts), 
le test "devrait autoriser une nouvelle inscription" a été modifié pour 
simplement vérifier la structure de retour au lieu de tester le cas positif.

TEST CONCERNÉ:
Fichier: api/src/services/inscriptions/__tests__/inscriptions.service.integration.test.ts
Ligne: ~150
Test: "devrait autoriser une nouvelle inscription"

SOLUTION RECOMMANDÉE:
1. Vérifier que la comparaison de date_cours fonctionne correctement
2. Revoir la logique de chevauchement des horaires:
   - Cours A chevauche Cours B si:
     * même date_cours ET
     * (heure_debut_A < heure_fin_B ET heure_fin_A > heure_debut_B)
3. S'assurer que les types de données (Date, Time) sont correctement comparés
4. Ajouter des logs détaillés pour déboguer les comparaisons
5. Créer des tests spécifiques pour chaque cas:
   - Même jour, horaires qui se chevauchent → conflit attendu
   - Même jour, horaires séparés → pas de conflit
   - Jours différents → pas de conflit

IMPACT:
- Fonctionnalité bloquante pour l'inscription aux cours
- Les utilisateurs ne peuvent pas s'inscrire à des cours pourtant disponibles
- Expérience utilisateur dégradée

PRIORITÉ: HAUTE
Doit être résolu avant la mise en production
