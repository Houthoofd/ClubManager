================================================================================
NOMENCLATURE APPLIQUÉE
================================================================================

1. Tous les fichiers suivent le pattern: nom-du-service.service.ts
2. Les fichiers helper suivent le pattern: nom-du-service.helpers.ts
3. Chaque service est dans son propre sous-dossier
4. Les sous-dossiers utilisent le kebab-case (health-check, rate-limit, etc.)

================================================================================
AVANTAGES DE LA NOUVELLE STRUCTURE
================================================================================

✅ Meilleure organisation et lisibilité
✅ Fichiers plus petits et plus maintenables (< 700 lignes)
✅ Nomenclature cohérente et prévisible
✅ Séparation claire des responsabilités
✅ Facilite la navigation dans le code
✅ Meilleure scalabilité pour de futurs ajouts
✅ Isolation des fonctionnalités par sous-dossier

================================================================================
IMPORTS MIS À JOUR
================================================================================

Le fichier services/index.ts a été mis à jour pour exporter tous les services
depuis leur nouvelle structure. Les imports dans le reste de l'application
doivent être mis à jour pour utiliser les nouveaux chemins.

Exemple:
  Ancien: import { userService } from './services/userService.js'
  Nouveau: import { userService } from './services/user/user.service.js'

  Ou via index: import { userService } from './services/index.js'
