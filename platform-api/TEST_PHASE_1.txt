4️⃣  TESTER LE RATE LIMITING
────────────────────────────────────────────────────────────────
# Script bash pour tester les limites
for i in {1..10}; do
  curl -i http://localhost:5000/api/users \
    -H "Host: demo-club.localhost:5000" \
    -H "Authorization: Bearer YOUR_TOKEN"
  echo "Request $i"
  sleep 0.1
done

# Vérifier les headers de réponse :
X-RateLimit-Limit: 500
X-RateLimit-Remaining: 499
X-RateLimit-Reset: 1705334400000

# Après 500 requêtes en 15min, devrait recevoir :
HTTP/1.1 429 Too Many Requests
{
  "error": "Rate limit exceeded for your plan",
  "retryAfter": 900,
  "limit": 500,
  "plan": "BASIC"
}


5️⃣  LANCER LES TESTS D'ISOLATION
────────────────────────────────────────────────────────────────
npm test -- src/__tests__/isolation/

# Tests qui devraient passer :
✓ User from tenant1 should not access data from tenant2
✓ Tenant resolver should correctly identify tenant from subdomain
✓ Users query should only return users from current tenant
✓ Creating data should automatically include tenantId
✓ Suspended tenant should not allow access

# Si échecs, vérifier :
- Les tenants de test existent
- Les middlewares sont appliqués
- L'isolation fonctionne

🐛 DEBUGGING
─────────────────────────────────────────────────────────────────

Problème : Health check échoue
→ Vérifier connexion Prisma
→ Vérifier variables d'environnement DATABASE_URL

Problème : Audit logs non créés
→ Vérifier migration appliquée
→ Vérifier middleware ajouté aux routes
→ Vérifier erreurs dans console

Problème : Rate limiting ne fonctionne pas
→ Vérifier NODE_ENV=production
→ Vérifier middleware appliqué dans app.ts
→ Vérifier tenant context présent

Problème : Tests d'isolation échouent
→ Créer tenants de test manuellement
→ Vérifier que les middlewares sont appliqués
→ Vérifier isolation au niveau DB

Problème : Backup échoue
→ Vérifier droits d'écriture /var/backups
→ Vérifier credentials MySQL
→ Vérifier espace disque disponible
