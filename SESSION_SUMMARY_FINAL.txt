┌─────────────────────────────────────────────────────────────────────┐
│ 🎯 PATTERN VALIDÉ - BEST PRACTICES                                  │
└─────────────────────────────────────────────────────────────────────┘

✅ DO:
• Lire le code source avant d'écrire les tests
• Utiliser des inputs réalistes basés sur les signatures
• Assertions spécifiques (toBe, toEqual, toContain, toHaveLength)
• Gérer les edge cases (null, undefined, empty, invalid)
• Tester le comportement réel, pas juste l'existence

❌ DON'T:
• Tests génériques avec toBeDefined() uniquement
• Appeler des fonctions sans paramètres requis
• Assumer des comportements sans vérifier le code
• Garder des tests qui échouent massivement (>20%)
• Utiliser des méthodes inexistantes (toEndWith vs endsWith)

Astuces techniques découvertes:
• Espaces dans formatage prix: \u00a0 (insécable) et \u202f (fine)
• Vitest n'a pas toEndWith() → utiliser .endsWith() avec .toBe(true)
• date-fns parseISO() ne lance pas d'exception → vérifier isNaN()
• formatUserFullName doit normaliser les espaces multiples
