2. CONFIGURATION JWT & SECRETS (CRITIQUE)
================================================================================

2.1 Générer un JWT_SECRET sécurisé
-----------------------------------

Sur votre machine locale ou le serveur:

node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"

Exemple de sortie:
a7f5c8d9e2b4f6a1c3e5d7b9f1a3c5e7d9b1f3a5c7e9d1b3f5a7c9e1d3b5f7a9c1e3d5b7f9a1c3e5d7b9f1a3c5e7d9

⚠️ IMPORTANT:
- Minimum 32 caractères
- Ne JAMAIS utiliser "your-secret-key" en production
- Ne JAMAIS commiter cette valeur dans Git
- Stocker dans un gestionnaire de secrets (AWS Secrets Manager, HashiCorp Vault, etc.)

2.2 Configuration recommandée
------------------------------

JWT_SECRET=<votre-clé-générée-ci-dessus>
JWT_EXPIRES_IN=900  # 15 minutes (en secondes)
REFRESH_TOKEN_EXPIRES_DAYS=7  # 7 jours

4. CONFIGURATION RATE LIMITING
================================================================================

4.1 Variables d'environnement
------------------------------

# Tentatives d'authentification
RATE_LIMIT_MAX_ATTEMPTS=5                    # 5 tentatives max
RATE_LIMIT_WINDOW_MINUTES=15                 # Dans une fenêtre de 15 min
RATE_LIMIT_BLOCK_DURATION_MINUTES=30         # Blocage de 30 min

# Rate limit global
GLOBAL_RATE_LIMIT_REQUESTS=100               # 100 req/IP
GLOBAL_RATE_LIMIT_WINDOW_MINUTES=15          # Par 15 minutes

# Inscriptions
REGISTER_RATE_LIMIT_REQUESTS=3               # 3 inscriptions/IP
REGISTER_RATE_LIMIT_WINDOW_MINUTES=60        # Par heure

# Récupération mot de passe
PASSWORD_RESET_RATE_LIMIT_REQUESTS=3         # 3 demandes
PASSWORD_RESET_RATE_LIMIT_WINDOW_MINUTES=15  # Par 15 minutes


4.2 Ajuster selon votre trafic
-------------------------------

Pour un site à fort trafic:
- Augmenter GLOBAL_RATE_LIMIT_REQUESTS (200-500)
- Garder les limites auth strictes pour la sécurité

Pour un site à faible trafic:
- Les valeurs par défaut sont appropriées
- Monitorer les faux positifs

5. REFRESH TOKENS
================================================================================

5.1 Comprendre le système
--------------------------

Access Token (JWT):
- Durée de vie courte (15 min recommandé)
- Contient les infos utilisateur
- Stocké côté client (mémoire, pas localStorage)
- Utilisé pour chaque requête API

Refresh Token:
- Durée de vie longue (7 jours recommandé)
- Stocké de manière sécurisée (httpOnly cookie)
- Utilisé uniquement pour renouveler l'access token
- Rotation automatique (un seul usage)


5.2 Flow de refresh
-------------------

1. Access token expire (15 min)
2. Client appelle /auth/refresh avec refresh token
3. API valide le refresh token
4. API révoque l'ancien refresh token
5. API génère nouveau access token + nouveau refresh token
6. Client utilise les nouveaux tokens


5.3 Sécurité des refresh tokens
--------------------------------

✅ Rotation automatique (implémentée)
✅ Révocation à la déconnexion
✅ Révocation au changement de mot de passe
✅ Tracking IP + User-Agent
✅ Expiration après 7 jours
✅ Nettoyage automatique des tokens expirés


5.4 Configuration recommandée
------------------------------

# Production
REFRESH_TOKEN_EXPIRES_DAYS=7

# Développement (plus court pour tester)
REFRESH_TOKEN_EXPIRES_DAYS=1

8.3 Configuration Nginx (reverse proxy)
----------------------------------------

# /etc/nginx/sites-available/clubmanager-api
server {
    listen 443 ssl http2;
    server_name api.votredomaine.com;

    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    # Security headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # Rate limiting global
    limit_req_zone $binary_remote_addr zone=api_limit:10m rate=100r/m;
    limit_req zone=api_limit burst=20 nodelay;

    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    # Auth endpoints - rate limiting strict
    location /auth/login {
        limit_req_zone $binary_remote_addr zone=login_limit:10m rate=5r/m;
        limit_req zone=login_limit burst=3 nodelay;
        proxy_pass http://localhost:3000;
    }

    location /auth/register {
        limit_req_zone $binary_remote_addr zone=register_limit:10m rate=3r/h;
        limit_req zone=register_limit burst=1 nodelay;
        proxy_pass http://localhost:3000;
    }
}

# Activer la config
ln -s /etc/nginx/sites-available/clubmanager-api /etc/nginx/sites-enabled/
nginx -t
systemctl reload nginx

9.4 Script de nettoyage (scripts/cleanup-tokens.js)
----------------------------------------------------

import { authService } from '../src/services/auth/auth.service.js';
import { nettoyerAnciennesTentatives } from '../src/middleware/rate-limit.js';

async function cleanup() {
  console.log('[Cleanup] Démarrage...');

  // Nettoyer les password reset tokens expirés
  const passwordTokens = await authService.nettoyerTokensExpires();
  console.log(`[Cleanup] ${passwordTokens.count} password tokens supprimés`);

  // Nettoyer les refresh tokens expirés/révoqués
  const refreshTokens = await authService.nettoyerRefreshTokens(30);
  console.log(`[Cleanup] ${refreshTokens} refresh tokens supprimés`);

  // Nettoyer les anciennes tentatives d'auth
  const authAttempts = await nettoyerAnciennesTentatives(30);
  console.log(`[Cleanup] ${authAttempts} auth attempts supprimés`);

  console.log('[Cleanup] Terminé');
  process.exit(0);
}

cleanup().catch(console.error);

10. ROLLBACK
================================================================================

10.1 Procédure de rollback rapide
----------------------------------

# 1. Arrêter l'application
pm2 stop clubmanager-api

# 2. Revenir à la version précédente
cd /path/to/clubmanager
git checkout <previous-commit-hash>

# 3. Réinstaller les dépendances
cd api
npm ci --production

# 4. Rebuild
npm run build

# 5. Redémarrer
pm2 restart clubmanager-api


10.2 Rollback des migrations
-----------------------------

# Si les nouvelles tables causent des problèmes:

# Option 1: Supprimer les tables
DROP TABLE IF EXISTS refresh_tokens;
DROP TABLE IF EXISTS auth_attempts;

# Option 2: Garder les tables mais désactiver les features
# Dans .env.production:
ENABLE_REFRESH_TOKENS=false
ENABLE_RATE_LIMITING=false

📞 SUPPORT & DÉPANNAGE
================================================================================

Problème: "Cannot connect to database"
Solution: Vérifier DATABASE_URL, firewall, et que MySQL est démarré

Problème: "JWT malformed" ou "invalid signature"
Solution: Vérifier que JWT_SECRET est identique partout, régénérer si changé

Problème: Trop de blocages rate limiting
Solution: Augmenter RATE_LIMIT_MAX_ATTEMPTS ou RATE_LIMIT_WINDOW_MINUTES

Problème: Refresh tokens ne marchent pas
Solution: Vérifier que la table existe, que REFRESH_TOKEN_EXPIRES_DAYS est set

Problème: Performance dégradée
Solution: Vérifier les index DB, augmenter instances PM2, activer cache
